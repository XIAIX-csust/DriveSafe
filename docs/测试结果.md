## 4. FP16 判定修复

```
调用前 model_kwargs = {}
调用后 model_kwargs = {'dtype': 'auto'}     ← transformers 就地修改了传入的 dict
bool(model_kwargs) = True                   ← 旧代码据此在 CPU 上误判为 FP16
```

修复后（CPU）输出 `Loaded Depth Anything v2 small model on cpu`，`half = False`；CUDA 上若实际 dtype 被覆盖会打印告警并回退 FP32 路径。

## 5. 节拍器 / 异步 worker 单测（纯标准库 + stub torch）

| 用例 | 结果 |
|---|---|
| FramePacer 离线 30→25 | 60 帧 → processed=51 / dropped=9（≈1/6） |
| FramePacer 离线 12.5→25 | 源慢 → 40 帧全处理、0 丢帧 |
| FramePacer 实时 12.5 fps 到达 | 0 误丢帧 |
| FramePacer 快于目标 | 6 帧耗时 0.204 s（被节流到 25 fps） |
| DepthAsyncWorker 独立 CUDA stream | stub 验证 `estimate_depth` 确实运行在 `torch.cuda.stream` 上下文内 |
| DepthAsyncWorker 最新帧优先 | 连发 5 帧 → latest 为最后一帧，dropped>0 |
| DepthAsyncWorker CPU 路径 | 不创建 stream，异步仍可用 |
| DepthAsyncWorker 单帧异常 | 不致命，后续帧继续处理 |

## 6. 复现步骤

```bash
# 1) 安装依赖（Windows 下 check_requirements 的 pip 引号有坑，建议先手动装齐）
pip install -r requirements_common.txt

# 2) 国内网络建议设置 HF 镜像（首次需下载 Depth Anything v2 权重）
$env:HF_ENDPOINT = "https://hf-mirror.com"

# 3) 跑 300 帧
python detect_3d_with_surface.py --source lanechange.mp4 --device cpu --no-view-img --max-frames 300 --no-pacing
```
