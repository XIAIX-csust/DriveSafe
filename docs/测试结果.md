## 2.1 检测阈值修正后的重新标定（conf=0.25 / iou=0.45）

原默认 `--conf-thres 0.01 --iou-thres 0.01` 几乎不做过滤，会带入大量低置信框。修正为 `0.25 / 0.45` 后重跑 300 帧：

| 项 | conf=0.01（exp82） | conf=0.25（exp84） |
|---|---|---|
| 总耗时 | 438.98 s（1.46 s/帧） | **208.45 s（0.69 s/帧）** |
| SCF 最大值 | 172.80 | 62.48 |
| SCF P50 / P95 / P99 | 91.0 / 107.3 / 171.6 | **22.6 / 26.4 / 42.8** |
| 深度 worker | done=220 dropped=79 | done=85 dropped=214 |
| 原始数据 | `exp82_300frames_frame_results.jsonl` | `exp84_300frames_conf025.jsonl` |

新分布**极窄**（P95=26.4 而 max=62.5），分位数阈值会退化成"在噪声上划线"，因此改为**锚定尾部**的绝对阈值：

| 判定 | 阈值 `50/40/30`（现行） | 若沿用 `110/100/90` |
|---|---|---|
| HIGH | 1 帧（0.3%） | 0 |
| MEDIUM | 5 帧（1.7%） | 0 |
| LOW | 3 帧（1.0%） | 0 |
| CLEAR | 291 帧（97.0%） | 300 帧（100%） |

端到端复核（20 帧，`runs/detect/exp85`）：frame 15 → MEDIUM(44.93)、frame 16 → LOW(35.55)、frame 18 → HIGH(62.52)，与离线重算一致。

> 说明：`lanechange.mp4` 是高速巡航场景（目标稳定在 9 m 左右、相对速度低），97% 帧为 CLEAR 属合理结果；如需更有区分度的标定，应换一段含真实危险工况的视频。

## 4. FP16 判定修复

```
调用前 model_kwargs = {}
调用后 model_kwargs = {'dtype': 'auto'}     ← transformers 就地修改了传入的 dict
bool(model_kwargs) = True                   ← 旧代码据此在 CPU 上误判为 FP16
```

修复后（CPU）输出 `Loaded Depth Anything v2 small model on cpu`，`half = False`；CUDA 上若实际 dtype 被覆盖会打印告警并回退 FP32 路径。

## 7. 路面模型 ROI（50%）+ 主/辅并行 的 A/B 实测

同一条视频前 150 帧，同机 CPU，只切换两个开关：

| 配置 | 命令差异 | 总耗时 | 每帧 | 路面隐患 |
|---|---|---|---|---|
| **A 新**（ROI 50% + 并行） | 默认 | **86.37 s** | **0.576 s** | 1 处（帧 86–95） |
| **B 旧**（整幅 + 串行） | `--road-roi-top 0 --no-road-parallel` | 95.20 s | 0.635 s | 0 处 |

→ **提速约 9%**（另一轮早期测量为 15.4%，说明存在运行间波动；单次结果请勿当作精确值）。
原始数据：`docs/test-results/exp104_150frames_roi50_parallel.jsonl`、`exp103_150frames_fullframe_serial.jsonl`。

### 关键坑：`masks.data` 不是 ROI 像素尺寸

`best` / `best_night` 是 **segment 模型**，输出掩码供 `surface_analysis` 计算隐患的真实像素面积/质心。
实测 ROI（1906×540）输入下 `masks.data` 的形状是 **(1, 192, 640)** —— 即 **letterbox 预处理分辨率**
（640 = 长边缩放结果，192 = 181 内容行 + stride 对齐 padding），而不是 ROI 像素空间。
因此 ROI 方案里掩码必须**先裁掉 padding、缩放到 ROI 尺寸、再整块贴回原图**；
直接按 ROI 坐标贴会让隐患 bbox/质心/面积/距离全部错位（实测 bbox 从 [1201,815,1725,974] 错成 [404,640,560,685]）。

## 8. 路面阈值标定复查（road_conf_thres / road_danger_level）

把 A（ROI）、B（整幅）与参考 exp84（300 帧 / 整幅 / conf=0.25）放在一起看：

| 指标 | A ROI(150帧) | B 整幅(150帧) | 参考 exp84(300帧) |
|---|---|---|---|
| 隐患总数 | 1（帧 86–95） | 0 | 6（帧 204–213） |
| 类型 | pothole | — | Pothole×4 + Crack×2 |
| 置信度 | 0.262 ~ 0.380 | — | 0.270 ~ 0.447 |
| bottom_ratio | 0.90（近处） | — | 0.312（远处裂缝）~ 0.894 |
| road_risk_score | 0.74 ~ 0.76 → level 2 | 0 | 0 ~ 0.89 → level 0/3 |

**结论与建议**

1. **`road_conf_thres = 0.25` 保持不动**。所有检出的路面隐患置信度都落在 **0.26 ~ 0.45**（100% < 0.5），
   说明 0.25 恰好是"卡在门口"的临界值：上调（如 0.3）会丢掉大部分检出，上调到 0.5 会全军覆没。
   若确实要提升召回，应下调到 0.15~0.20，但**必须先验证误检率**。
2. **`road_danger_level`（0.8 / 0.55 / 0.25）无需改**。450 帧里实际出现了 level 0（远处裂缝，severity 0.16 → 判定"不构成危险"，合理）、level 2（近处中等坑洼）、level 3（近处大坑洼）三档，分布合理；**level 1 从未出现，该档位尚未被数据验证**。
3. ⚠️ **ROI 50% 有确定的召回风险**：参考 run 中那处 `Crack`（bbox y1=285，bottom_ratio 0.312）位于画面 **y<540**，
   ROI 50% 下**完全看不到**。也就是说 ROI 只能保留画面下半部的隐患；
   若在意远处缺陷，应把 `--road-roi-top` 降到 **0.25~0.3**（相应地省不了那么多时间）。
4. ROI 会**改变模型的检出行为**：同样帧 86–95，`best_night`（那几帧被判定为夜）在整幅上 0 框、在 ROI 上 1 框（conf 0.38）。
   这属于输入构图变化带来的模型行为差异 —— 可能是召回归回，也可能是误检，**需要真值标注才能定性**。
